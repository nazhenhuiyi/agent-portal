# Agent 展示系统：使用、设计与学习资料

安装与持续运行见 [部署说明](deployment/README.md)，可按平台选择外部进程管理工具。

产品设计从 [产品设计目录](product-design/README.md) 开始。当前先明确产品目标和边界，再根据手机运行机制推导更新流程、协议与实现。

下面两套手册保留为领域学习资料，其中的教学例子不等于已经采纳的产品方案。

我们要理解的是：一个原生 App 除了自己的页面，还能怎样接入手机系统，向用户呈现信息、提供操作入口，并在系统允许的时机更新内容。

推送通知是其中一个板块。桌面、动态壁纸、小组件是另外几种系统接入方式。先学习各自的工作机制和彼此的关系，再讨论产品组合、API 和数据结构。

| 板块 | 学习入口 | 主要问题 |
|---|---|---|
| Android 桌面与系统界面 | [Android 系统能力学习手册](android-system-capabilities/README.md) | 谁拥有主屏幕？壁纸、小组件和锁屏卡片分别怎样接入？ |
| 移动推送通知 | [推送通知学习手册](push-notifications/README.md) | 服务器消息如何进入手机，成为通知并打开内容？ |

想先建立整体关系，从 [桌面、壁纸和小组件分别是什么](android-system-capabilities/01-capability-map.md) 开始；想深入消息传递，再进入推送通知手册。

Android 优先，各端采用原生技术。当前已有服务端及 Android 首轮实现；运行方式以仓库 README 和部署说明为准。后续能力及其研究状态见 [Android 手册的扩展地图](android-system-capabilities/README.md#后续扩展)。
