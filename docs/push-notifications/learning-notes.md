## 练习一：为三类消息定义语义

不要先填 API 字段。先用自然语言回答：给谁、多久有效、旧消息是否可替代、没有推送时如何看到内容、点击后去哪里。

| 场景 | 消息时效 | 可否替代旧消息 | 应保留的事实 | 点击目标 |
|---|---|---|---|---|
| 有人按门铃 | 待填写 | 待填写 | 待填写 | 待填写 |
| 报告生成完成 | 待填写 | 待填写 | 待填写 | 待填写 |
| 后台任务进度更新 | 待填写 | 待填写 | 待填写 | 待填写 |

思考：报告通知过期之后，报告是否仍应在 App 中可见？两条同一任务的进度更新，与两个不同任务完成，是否应使用同一个折叠规则？

## 练习二：解释一次“没收到”

按顺序寻找证据：

1. 业务事件有没有发生并保存？
2. 发送请求是否正确、平台是否接受？
3. 目标注册标识或订阅是否有效？
4. 设备是否在线，相关平台服务是否可达？
5. 消息是否过期、被折叠或受到限流？
6. 设备端是否能观察到接收？
7. 通知权限、分类和系统展示设置是否允许提醒？
8. 是否已经收到，只是安静地放在通知中心？

把“没响铃”与“消息未到达”分开记录。若某一步没有观测能力，写“未知”，不要猜测。

- 产品更重视少维护、及时送达、可自建，还是最小外部依赖？
